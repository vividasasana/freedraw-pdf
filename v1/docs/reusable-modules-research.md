# Reusable modules for Freedraw PDF

_Checked 2026-08-23. Sources are limited to official documentation and primary GitHub repositories/source._

## Executive decision

Keep Apple Pencil/finger arbitration and Canvas 2D overlay ownership inside the plugin. Continue using `perfect-freehand`; adopt `rbush` behind a page-scoped spatial-index seam; keep Obsidian's host command/menu and PDF.js facilities; and build small local adapters/registries around them. Do not introduce a general gesture recognizer or canvas scene graph.

The current project already has the right raw materials: one runtime dependency in [`package.json`](../package.json), input-policy and pressure normalization in [`pointerInput.ts`](../src/pointer/pointerInput.ts), pressure geometry in [`inkEngine.ts`](../src/ink/inkEngine.ts), bounds/geometry modules under [`src/annotation`](../src/annotation), full-document history snapshots plus a special stroke-add entry in [`main.ts`](../main.ts), and a host-PDF.js adapter in [`nativePdfJs.ts`](../src/pdf/nativePdfJs.ts). The opportunity is to deepen those seams, not replace them with a framework.

## Platform constraint

Pointer Events already expose device type, normalized pressure, capture, and coalesced/predicted samples. Crucially, browser panning/zooming is controlled by `touch-action`; canceling a pointer event is not the mechanism for suppressing an already-allowed direct manipulation. The specification also reserves `pressure = 0.5` for active hardware that cannot report pressure, so that value is not evidence of a stylus. [W3C Pointer Events](https://www.w3.org/TR/pointerevents/)

WebKit supports generic pointer events for mouse, touch, and stylus; Safari 18.2 added coalesced/predicted events and Apple Pencil altitude/azimuth fields. This supports a local, pointer-down-first state machine: classify the native event; route pen/stylus to ink; leave the primary finger available for pan; promote two accepted touch pointers to pinch; and retain pointer capture only for the chosen ink pointer. [WebKit Pointer Events introduction](https://webkit.org/blog/9674/new-webkit-features-in-safari-13/) · [Safari 18.2 input additions](https://webkit.org/blog/16301/webkit-features-in-safari-18-2/)

## Recommended module seams

1. **`InputArbiter`** (local): the only owner of native Pointer/Touch/WebKit events and `touch-action`; emits `InkSample`, `PanIntent`, or `PinchIntent`. Adapt PointerTracker's ledger, not its package.
2. **`InkGeometry`** (existing, deepen): owns sample conditioning and `perfect-freehand`; returns renderable outlines without knowing DOM events.
3. **`AnnotationHistory`** (local): executes semantic commands and returns `affectedPages`; undo/redo, save scheduling, spatial-index updates, and redraw consume the same result. This is the prerequisite to any future Immer experiment.
4. **`SpatialIndex`** (new adapter): page-scoped RBush broad phase with current exact geometry as the narrow phase.
5. **`CommandRegistry`** (local): one descriptor source adapted to Obsidian commands and menus.
6. **`PdfSurface` / `AnnotationRenderer`** (existing, deepen): PDF.js host adapter owns page viewport/rendering; annotation Canvas owns only normalized overlay rendering and interaction previews.

## Skill applicability

- **Materially helpful:** `research` enforced primary-source citations and a single report artifact; `codebase-design` supplied the module/interface/seam/depth test used to reject pass-through or framework-heavy choices; `obsidian` supplied host lifecycle, command/menu, mobile, and popout-window constraints.
- **Not applicable to this research pass:** `tdd`; no runtime behavior was changed. It becomes useful during adoption for pointer-arbitration traces, command round trips, RBush-versus-linear result equivalence, and rotated/zoomed overlay integration tests.
- **Runtime-code note:** these skills are instruction sets, not libraries; none supplies runtime code. The recommended runtime reuse is limited to existing `perfect-freehand`, proposed `rbush`, and host-provided Obsidian/PDF.js facilities.
